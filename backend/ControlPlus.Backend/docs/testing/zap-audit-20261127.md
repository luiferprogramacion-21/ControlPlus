# Auditoría de seguridad con OWASP ZAP

## 27 de noviembre de 2026

Esta auditoría ataca la API y la pantalla de ControlPlus con OWASP ZAP 2.17 para buscar fallas de
seguridad que las pruebas automáticas no cubren. Forma parte de la auditoría ISO
(`docs/testing/iso-square-audit-20261127.md`, hallazgo `ISO-AUD-008`).

Nunca se escaneó la base `controlplus`, el servicio instalado en la tienda ni el puerto 5000. Todo corrió
contra una copia aislada que se crea y se borra en cada ejecución.

## Entorno aislado

`scripts/security/zap/Invoke-ZapAudit.ps1` prepara un entorno nuevo en cada ejecución:

- **PostgreSQL temporal:**
  - se crea con `initdb` en `%TEMP%`;
  - escucha solo en `127.0.0.1`, en un puerto libre distinto de 5432;
  - usa contraseña aleatoria con `scram-sha-256`;
  - aloja la base `controlplus_test_<id>`.
- **Migraciones:** `Prepare-ZapDatabase.cs` las aplica todas. Rechaza cualquier base que no se llame
  `controlplus_test_*`, el puerto 5432 y una base que ya tenga migraciones.
- **API publicada en `%TEMP%`:**
  - arranca un momento en modo `Testing` solo para descargar el OpenAPI (170 rutas);
  - después arranca en modo `Production`, la configuración de la tienda (contraseñas de 4 números, OpenAPI
    protegido, encabezados de seguridad), en un puerto libre distinto de 5000;
  - los respaldos y el correo quedan apagados.
- **Excepción de la base aislada:** el modo `Production` solo acepta la base `controlplus` con
  `controlplus_app`. La auditoría enciende `Security:AllowIsolatedTestDatabase` en la variable de su propio
  proceso. Esa opción solo admite bases `controlplus_test_*` o `controlplus_e2e_*` en `127.0.0.1`, siempre
  con contraseña. Véase `docs/security.md`.
- **Usuarios:** se crean `admin.zap`, `supervisor.zap` y `cajero.zap`. Sus contraseñas de 4 números y la
  clave maestra se generan al azar en memoria y nunca se escriben en pantalla ni en archivos.
- **Sesión:** cada fase con sesión recibe un token nuevo de su rol en la variable `ZAP_AUTH_HEADER_VALUE`,
  que existe solo en el proceso de ZAP.
- **Exclusiones del ataque:**
  - perfiles de impresora y cajón, que crearían dispositivos reales;
  - en las fases con sesión, además, `/api/auth/*`, que cerraría o cambiaría la sesión del escaneo.
- **Evidencia:** los informes JSON y HTML, el registro de la API y un resumen por fase quedan en
  `%USERPROFILE%\ControlPlus-Evidence\Zap-<fecha>-<id>`, fuera del repositorio. Al terminar, la API y
  PostgreSQL se detienen y se borran la base, la sesión de ZAP y los archivos temporales.

Para repetirla, en PowerShell normal (no hace falta Administrador), desde `backend\ControlPlus.Backend`:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\security\zap\Invoke-ZapAudit.ps1
```

Una ejecución completa toma cerca de dos horas. Para correr solo algunas fases:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "& '.\scripts\security\zap\Invoke-ZapAudit.ps1' -Phases Pasivo,Administrador -ActiveScanMinutes 15"
```

Termina con `ZAP_AUDIT_OK`.

## Hallazgos corregidos

### ZAP-PAS-001 política de contenido ausente

- **Alerta:** Content Security Policy (CSP) Header Not Set, riesgo medio (regla 10038), en la pantalla.
- **Riesgo:** sin CSP, un script inyectado podría ejecutarse en el navegador del cajero.
- **Corrección:**
  - la API envía en toda respuesta `ControlPlus.Api/Security/SecurityHeaders.cs`:
    `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:;
    font-src 'self' data:; connect-src 'self'; frame-src 'self'; frame-ancestors 'none'; base-uri 'self';
    form-action 'self'; object-src 'none'`;
  - el build de producción de Angular dejaba un script en línea en `index.html` (carga diferida de la hoja
    de estilos), que esa política bloquearía; `angular.json` apaga esa optimización (`inlineCritical: false`)
    y `index.html` queda con un solo script propio;
  - el CI falla si `index.html` vuelve a traer un script en línea.
- **Prueba:** `SecurityHeadersTests` comprueba la política exacta, `script-src 'self'`,
  `frame-ancestors 'none'`, `object-src 'none'` y la ausencia de `unsafe-eval`.
- **Estado:** corregido. La repetición pasiva ya no muestra la alerta.

### ZAP-ACT-001 carácter nulo en el inicio de sesión

- **Evidencia:** en la primera ejecución completa, un usuario con el carácter nulo (`\u0000`) en
  `POST /api/auth/login` llegó a PostgreSQL, que no admite ese carácter, y la API respondió 500.
- **Corrección:** `ControlPlus.Api/Security/NullCharacterGuard.cs` hace dos cosas:
  - el lector JSON rechaza todo texto con el carácter nulo;
  - un filtro rechaza la ruta o los parámetros de consulta que lo traigan.

  Ambos responden 400 `validation.failed` («La solicitud contiene un carácter no permitido.») antes de
  llegar a la base.
- **Prueba:** `NullCharacterRequestTests` cubre el cuerpo JSON, el parámetro de consulta, una solicitud normal
  y el lector.
- **Estado:** corregido. Las fases posteriores no registran ese error.

### ZAP-ACT-002 textos más largos que la base al crear permisos

- **Evidencia:**
  - los 12 errores 500 de la fase Administrador fueron `POST /api/permissions` con un código de más de 100
    caracteres: PostgreSQL respondió `22001 value too long for type character varying(100)`;
  - la alerta «Format String Error» (regla 30002) es la misma solicitud: ZAP la marcó porque la conexión
    terminó con error.
- **Riesgo:** bajo. Solo lo alcanza un Administrador y no se guardaba nada, pero un 500 no explica qué
  corregir y llena el registro de errores.
- **Corrección:** `RoleManagementService` valida el largo de cada campo con su columna, después de quitar
  los espacios de los extremos, y responde 400 con el máximo permitido:
  - permiso: código 100, nombre 150, módulo 50 y descripción 500;
  - rol: código 50 y nombre 100.
- **Prueba:** `SecurityApiFlowTests.PermissionAndRoleTexts_LongerThanTheirColumns_AreRejectedWithBadRequest`
  (integración con PostgreSQL, en el CI) comprueba tres cosas:
  - cada campo demasiado largo responde 400 y no crea nada;
  - el largo exacto de cada columna sí se guarda;
  - editar con un nombre largo también responde 400.
- **Estado:** corregido. Véase la repetición siguiente.

## Riesgo residual

### ZAP-PAS-002 estilos en línea permitidos

- **Alerta:** CSP: style-src unsafe-inline, riesgo medio (regla 10055). Aparece después de agregar la política.
- **Motivo:** Angular y Angular Material insertan estilos en línea al dibujar cada pantalla. Los tickets,
  carnés y etiquetas que se imprimen desde el navegador también llevan sus propios estilos. Sin
  `'unsafe-inline'` en `style-src` esas pantallas se verían mal.
- **Por qué se acepta por ahora:**
  - los scripts siguen limitados a `'self'`, sin `unsafe-inline` ni `unsafe-eval`;
  - un estilo inyectado no puede ejecutar código;
  - Angular escapa los datos que muestra.
- **Endurecimiento posible:** un `nonce` por respuesta, con `ngCspNonce`, para los estilos de Angular. Exige
  que la API reescriba `index.html` en cada solicitud y revisar las impresiones del navegador. No se hace
  antes de la entrega.
- **Estado:** aceptado provisionalmente; se informa al usuario.

## Ejecuciones descartadas

- **`Zap-20261127T201857Z-e2b1…`:** se detuvo antes de escanear, sin informes.
- **`Zap-20261127T203611Z-ed32…`:** solo corrió la fase pasiva, con la CSP todavía ausente.
- **Fases con sesión de `Zap-20261127T210349Z-e5f8…`:** todas las respuestas fueron 401. El escaneo usaba
  una regla del Replacer con `Bearer ${CP_ZAP_TOKEN}`, y ZAP no reemplaza variables en ese campo: enviaba el
  texto tal cual. Se comprobó con un servidor de eco local y se cambió a `ZAP_AUTH_HEADER_VALUE`. Desde
  entonces el script cuenta las respuestas por fase, y una fase con sesión debe mostrar respuestas 200 y 403.

## Límites

- **No es una prueba de penetración manual.** ZAP no evalúa reglas de negocio como descuentos, caja o
  autorizaciones; esas reglas las cubren las pruebas de integración.
- **Exclusiones:** no se atacaron la impresora, el cajón ni el cierre de sesión.
- **Sin TLS.** El escaneo usa HTTP local, como la tienda.
- **La intensidad media no prueba todas las variantes** de cada ataque.
